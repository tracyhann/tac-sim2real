# VTLA: N0-VTLA policy on the glove dataset, state actions (VTS) vs force-informed actions (VTF)

Two policy arms built on [N0-VTLA](https://github.com/neoteai/N0-VTLA) (a π0.5-style vision-tactile-language-action model with
a latent tactile pathway; paper arXiv 2607.23782), trained on the mug pick-and-place glove dataset. The arms share everything
(inputs, data, steps, seeds, base weights) except the **action target**:

| arm | action chunk (32-D, the repo's container) | what it tests |
|---|---|---|
| **VTS** | `[wrist xyz, wrist rot6d, closure, 22 measured finger joints]` = the future hand state | the paper's recipe on our data as is |
| **VTF** | `[wrist xyz, wrist rot6d, grip force (N), 22 commanded finger joints]` | does a force-informed action help |

Why VTF: once a finger touches the mug it stops at the surface, so the measured joint angles barely change with grip force
(100 g -> 300 g of water changed them by about 1 deg). A policy that outputs measured angles would put the fingers on the mug
and not squeeze. The simulation's fingers are position servos, so the force lives in the gap between the commanded and the
measured angle, F ~ kp (q_cmd - q) (the DexForce argument). VTF outputs the commanded angles (the servo targets of the
replay) and the total commanded grip force in the slot the canonical layout keeps for the gripper.

## 1. Model (what is reused, swapped, added)

- **Reused unchanged** (imported from the N0-VTLA repo at commit `03a0ce4`, not copied): PaliGemma 3B prefix (camera image +
  language + the state as 256-bin text tokens), Gemma 300M flow-matching action expert, the latent tactile path: tactile
  tokens g -> predictor (`tactile_kv`: g is the only key/value, the vision-language prefix only conditions the queries) ->
  5 latent tokens z -> `z_proj` -> zero-initialised gate -> prepended to the action suffix (actions attend z and the prefix,
  the prefix never sees z). Initialised from the pretrained base [NeoteAI/n0-vtla-base](https://huggingface.co/NeoteAI/n0-vtla-base)
  (8.3 GB; predictor, z_proj and gate included).
- **Swapped**: the tactile encoder. The repo encodes optical tactile *images* with a frozen DINOv2. Our glove gives 880 force
  values on 15 pads, each a full rows x cols grid (distal pads 9 x 8, thumb distal 16 x 10, thenar / hypothenar 13 x 8, the
  others 3 x 8 or 4 x 8), so `code/taxel_encoder.py` turns them into 16 tokens (one per pad + one whole-hand token), the same
  layout as the repo's CLS + pooled tokens. Touch is a value array here, never an image. Default encoder `grid`
  (`--tactile_encoder grid`): every taxel gets the same force embedding plus a Fourier encoding of its (row, col) inside its pad
  and the pad's embedding; each pad pools its taxels by attention and adds explicit "where" summaries (total force, contact
  area, force-weighted centroid and spread); the hand token pools the pads. This keeps the spatial structure a ViT would see
  (a contact that moves by one row changes the tokens a little, a press on another finger a lot: 0.6 vs 7.5 at
  initialisation). `--tactile_encoder mlp` is the first version (a separate weight per taxel slot, no position encoding),
  kept for the ablation.
- **Added**: the paper's Stage-1 predictor objective, which the repo does not ship: symmetric InfoNCE between the pooled z and
  z* = f_enc(touch[t+H] - touch[t]) (f_enc = a frozen random projection of the touch change and its per-pad totals), plus an
  L1 reconstruction of the per-pad touch change from z.
- **Stages** (the paper's three, all in one run, `code/train_vtla.py`):
  1. `pred`: only the tactile stack (encoder, predictor, reconstruction head) on the Stage-1 objective; policy frozen.
  2. `align`: z_proj, gate and action expert on the action loss, with the action queries cut off from the vision-language
     prefix, so actions can only use z.
  3. `joint`: everything on the action loss (optionally + `--aux_weight` x Stage-1 loss); the tactile stack and z_proj at
     0.1 x the learning rate, as in the repo's post-training recipe.

## 2. Data

Dataset: [tracyhan816/mug-video-touch-lora-hf25](https://huggingface.co/datasets/tracyhan816/mug-video-touch-lora-hf25)
(CC BY-NC 4.0). Each row = one 5 s clip at 16 fps (81 frames): the head-camera video (generated by model W from a physics
replay), the left glove's touch (880 taxels, N), the simulated hand pose, prompts and parameters.

The VTLA arms read one extra file per row, `vtla/<id>.npz`, built from the simulation replays by the authors
(`code/build_vtla_labels.py`, needs the replays, which are not public):

| key | shape | meaning |
|---|---|---|
| `state` | 81 x 32 | `[wrist xyz (m), wrist rot6d, closure (rad), 22 measured joints (rad)]` = both arms' proprioception |
| `act_vts` | 81 x 32 | = `state` |
| `act_vtf` | 81 x 32 | `[wrist xyz, wrist rot6d, grip force (N), 22 commanded joints q_cmd]` |
| `q_cmd`, `q` | 81 x 22 | commanded / measured finger joints |
| `f_cmd`, `f_glove`, `f_sim` | 81 x 6 | per part (thumb, index, middle, ring, little, palm): commanded force (glove target x the row's grip scale), the glove target, the simulated force (N) |
| `tactile` | 81 x 880 | the glove touch (N above baseline) |
| `loaded`, `joint_names`, `t`, `t_sim` | | which fingers the glove loads, joint order, video / simulation time |

`q_cmd` = the replay's servo target: grasp pose + the grip controller's closing offset (weighted per joint) + the pulp
offset on the distal joint, for the fingers the glove loads; silent fingers comply to contact with unrecorded offsets, so
`q_cmd = q` there. Status: `vtla/` exists for the 25 released rows; it is published together with the expanded dataset
(about 380 rows, in progress), until then ask the authors for it.

Per sample (one frame t of one row): image = frame t (224 x 224, padded), wrist cameras = zero images with mask off, state
quantile-normalised to [-1, 1] and written into the prompt, touch = touch[t] / tactile scale (99th percentile of active
taxels), action chunk = act[t+1 .. t+16] with the wrist and joint slots as deltas to state[t] and slot 9 absolute.

**Prompt** (`--prompt observable`, default): task instruction + the perturbation clauses that are instructions or visible
(speed, shaking, posture, grip strength). Mass (water) and friction are left out: they are hidden physics that touch should
reveal; writing them into the prompt would put the answer into the input. `--prompt full` keeps the dataset's full text (an
oracle upper bound).

## 3. Setup (one GPU machine, Linux, CUDA)

```bash
R2S2R=/data/r2s2r bash setup.sh
```

Clones N0-VTLA at `03a0ce4`, creates a Python 3.11 venv with the repo's pinned requirements (torch 2.7.1, transformers
4.53.2) and its `transformers_replace` patch, downloads the base checkpoint and the PaliGemma tokenizer, downloads the
dataset, runs the CPU unit test (`code/test_vtla.py`, tiny model, no weights, about 1 min). About 35 GB of disk.

## 4. Smoke test (one GPU, about 30 min)

```bash
R2S2R=/data/r2s2r bash smoke.sh
```

Both arms, 30 steps per stage from the base checkpoint, then the open-loop eval on 3 rows. It shows the code runs end to end
with the real weights; the numbers mean nothing at this length.

## 5. Training

```bash
R=/data/r2s2r; DS=$R/outputs/R2S2V_mug/hf25/dataset; PY=$R/envs/vtla/bin/python
export N0VTLA_DATA_HOME=$R/cache/n0vtla HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1
cd code
for arm in vts vtf; do
  $PY train_vtla.py --arm $arm --data $DS --base $R/models/n0-vtla-base --out $R/outputs/vtla/$arm \
      --stages pred:500,align:500,joint:3000 --batch 16 --cache $R/cache/vtla_frames --val_groups <held-out group>
done
```

- One 80-141 GB GPU, bf16, gradient checkpointing; each stage is saved (`<out>/<stage>/model.safetensors`, about 7 GB, plus
  `norm_stats.json` and `run.json`); `--save last` keeps only the last stage. `<out>/final` points at the last stage.
- Hold out whole groups or rows (`--val_groups`, `--val_ids`): neighbouring frames of one clip are near duplicates, so a
  frame-level split says nothing.
- Learning rates: pred 1e-4, align 5e-5, joint 2e-5 (the repo's post-training peak), cosine to 10 %, 100 warm-up steps,
  AdamW (0.9, 0.95), gradient clip 1.0.

## 6. Evaluation (open loop)

```bash
$PY eval_vtla.py --ckpt $R/outputs/vtla/vtf/final --data $DS --stride 8      # the checkpoint's held-out rows by default
```

Per start frame: sample the chunk (10 Euler steps, fixed noise), undo normalisation and deltas, compare with the arm's
target over the chunk: wrist position (mm), wrist rotation (deg), joint slots (deg), slot 9 (closure deg / grip force N).
Baseline `hold` = repeat the current action. Latent probes from the paper: `z_top1` (retrieve the matching future-touch
target among the evaluated starts; chance 1/n) and `z_shift_touch` / `z_shift_image` (how far z moves when only the touch /
only the image is swapped; the paper reports about 0.9 vs 0.2).

## 7. Caveats

- **Command vs outcome leak**: the grip controller makes the simulated force follow the glove, so VTF's grip force tracks the
  total touch (r = 0.95-0.97 on the 25 rows). A policy can then score well by copying the current touch into the next grip.
  Always compare with `hold`, and look at the rows where command and outcome part (grip 30 %, friction x 0.5, 6 cm shake).
- **Mass is not learnable from this data**: the replay follows the recorded glove force whatever the mug weighs, so touch and
  joints hardly change with water (100 / 200 / 300 g: total touch 31 N each). Learning a hidden mass needs rollouts whose
  grip responds to the load.
- In the claw and rim-pinch postures q_cmd - q is negative on some joints (the mug wall holds a finger more flexed than its
  target, e.g. rim pinch index -46 deg at 10.6 N); the hand pose matches the replay exactly there.
- The image is the W-generated video of the replay, not a real camera; there are no wrist cameras; horizon 16 frames (1 s)
  instead of the base's 50 steps.
- 25 rows = smoke tests only. The expanded set (about 380 rows: jittered grasps, motion / grip / props / posture grid) is the
  training set for real runs.


- Hypotheses: H1 B keeps the mug in hand when its chunks are executed in the simulator more often than A, even at similar

- Limits: mass cannot be tested with this data (the replay's grip does not respond to the load); two source clips only.

## 11. Does the touch-calibrated simulation data help? (three arms, 2026-10-26)

A real hand controls either joint angles or force, not both, so the policy gets no touch input and outputs positions only. What
differs between the arms is only where the finger labels come from. Same model (pi0.5 policy, joint stage only, no tactile
tokens), same 300-row size, same 1500 steps at batch 32 (about 1 h on one H200), same inputs (head-camera video, measured hand
state, prompt).

| run | training rows | finger action label | what it stands for |
|---|---|---|---|
| T-obs | `dataset_cmp_t` | observed hand pose (`act_obs`) | a video of a human hand: what the fingers did |
| T-cmd | `dataset_cmp_t` | commanded pose of the touch-calibrated replay (`act_cmd`, logged servo targets) | our tactile sim data: where the fingers must aim so the grip force matches the glove (N0-VTLA's commanded-target convention) |
| V-cmd | `dataset_cmp_v` | commanded pose of the vision-only replay (clip config `touch: false`) | sim data without touch: fixed closing offset, release when the tracked mug stops |

```bash
R2S2R=<root> envs/scenemug/bin/python code/build_cmp.py      # the two 300-row sets + 36 simulated test rows (needs the replays)
R2S2R=<root> envs/scenemug/bin/python code/build_gt.py       # the held-out recordings (needs datagen/vision_gt_step.sh first)
R2S2R=<root> bash run_cmp.sh T-cmd 1500                      # train + predict the 36 simulated test rows
R2S2R=<root> bash predict_gt.sh T-cmd 4                       # the two held-out recordings, 10 noise seeds, re-plan every 4 frames
```

- Training sets. `dataset_cmp_t` = 100 rows per perturbation batch (wrist jitter 112, finger / grasp jitter 100, relocated
  set-down 88), both source clips. `dataset_cmp_v` = 300 valid vision-only twins of the same perturbations. The vision-only
  replay tips the mug at release on clip 53780879, so its composition is skewed: edf jitter 144, finger jitter edf 60 / 538 52,
  relocate edf 44.
- Main test = the held-out recordings 4397541c and 55494490 (user 2026-10-26), never a training row or a perturbation source.
  Input = the real head-camera clip resampled to 81 frames at 16 fps, plus the recording's measured hand state. The physics test
  re-runs each recording in the simulator (cf_relocate variant `rec`). The wrist follows the recording. The 22 finger servos
  follow the policy's predicted joint targets from frame 1 to the end, so the grasp, hold, set-down and release are the policy's.
  10 noise seeds per recording and arm = 20 trials per arm.
- References on the same scenes: `meas` / `cmd` = the recording's own measured angles / logged servo targets at 100 Hz;
  `L-obs` / `L-cmd` = the recording's labels at the policy's 16 fps (a perfect T-obs / T-cmd policy).
- Metrics (`scene_mug datagen/policy_gt.sh` -> `runs/datagen/policy_gt.json`): success (airborne slip <= 5 mm and 5 deg, not
  dropped, tilt < 30 deg, rests within 30 mm of the recording), dropped, tipped, carried force against the recording, release
  delay, and open-loop joint error against both labels. Secondary test: the 36 simulated test rows (`policy_batch.sh`).
- Expected if the touch data matter: T-cmd holds the mug about as often as `L-cmd`. T-obs drops it more often, with lower
  carried force, like the `meas` oracle (on the simulated rows meas held 29/37 against cmd 38/38). V-cmd squeezes far too hard
  (130-210 N against 36-51 N on the replays) or lets go at the wrong time.
- Execution protocol: `predict_cmp.py --every 4` (`predict_gt.sh <run> 4`) re-plans every 4 frames and executes the first 4 actions
  of each chunk, the usual pi0.5 practice. Executing whole 16-frame chunks fails at the release in every arm: both recordings let
  go at frames 64-70, and the chunk from frame 64 alone (hand still closed in the real video) keeps the fingers about 7 deg too
  closed, so the retreating wrist drags the mug 7-9 cm. The training clips let go at frame 66.7, so this is not a timing shift.

  tracks the glove. The policies never see the glove (no touch input), so their rows are a fair test.
- Commanded against observed pose survives with the glove as the judge. On 4397541c T-cmd beats T-obs on total r (+0.13,

- No arm loads a glove-silent part. On 55494490 the glove loads the middle finger but the twin never does, not even the

- The test twins use the canonical mug tracks, whose handle yaw is wrong (D77: 104 deg on 4397541c, 96 deg on 55494490). The
